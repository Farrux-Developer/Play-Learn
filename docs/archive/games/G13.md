# GDD G13 — Samarqand–Toshkent marshruti (Graphs, BFS/DFS & Recursion)

- **Unit & Skills**: `U9` · `S129`, `S130`, `S132`, `S134`–`S142`
- **Chunk Budget**: `<= 34 KB gz`

## 1. Core Loop & Intrinsic Integration
An interactive Silk Road transit & directory graph connects cities/nodes across weighted/unweighted edges:
- **Mode A (BFS vs DFS Frontier)**: Step through graph exploration by maintaining the active **Queue (`Navbat` for BFS)** or **Stack (`Stek` for DFS)** and `visited` set (`Tashrif buyurilganlar`) to guarantee the fewest hops (`BFS`) or detect cycles without looping infinitely.
- **Mode B (Recursion Tree)**: Trace or prune a recursive call tree (`fib` memoization) to eliminate redundant duplicate branches.

## 2. Controls & Accessibility
- Interactive SVG graph with keyboard `Tab`/`Arrow` node traversal, node `Enter` to expand neighbors, toggleable adjacency list table (`role="table"`), step-by-step Queue/Stack inspector.

## 3. Levels (15+: 5 Authored + Seeded Generator + Solver)
- **Levels 1–5 (Authored)**: (1) Recursion base case guard; (2) Tree pre-order/level-order traversal; (3) BFS shortest-hop route (Samarqand → Toshkent); (4) Cycle trap when `visited` is missing in DFS; (5) Memoization pruning on Fibonacci recursion tree.
- **Levels 6–15+ (Procedural Seeded)**: Connected planar-friendly graphs (`6..12` nodes, guaranteed path & at least 1 cycle) generated from `seed`; built-in BFS/DFS solver verifies unique shortest hop count and reachable frontier.

## 4. Feedback & Mastery
- Replays the exact node expansion order (`frontier`) and highlights where forgetting `visited` caused an infinite cycle.
