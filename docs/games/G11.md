# GDD G11 — Xesh-ombor (Array Indexing, Dicts & Hash Collisions)

- **Unit & Skills**: `U7` · `S098`, `S099`, `S108`–`S111`, `S113`
- **Chunk Budget**: `<= 26 KB gz`

## 1. Core Loop & Intrinsic Integration
A shelf warehouse stores items either by **0-based numeric index** (`ombor[i]`) or via a **hash bucket rule** (`hash(kalit) % M`):
- Learners diagnose `IndexOutOfRange` bugs (`i <= len` instead of `< len`), resolve **hash collisions** using chaining (bucket lists) or linear probing (`(h + step) % M`), and aggregate incoming event logs into a **frequency map (`Lugʻat`)** in `O(1)` average lookup steps rather than `O(N)` scanning.

## 2. Controls & Accessibility
- Grid/bucket slots navigable via `ArrowLeft/ArrowRight/Enter`, probe-step simulator, clear numeric step counter showing lookups saved (`O(1)` vs `O(N)`).

## 3. Levels (15+: 5 Authored + Seeded Generator + Solver)
- **Levels 1–5 (Authored)**: (1) 0-indexed shelf access & `len - 1`; (2) Key lookup vs missing-key safe guard; (3) Modulo hash placement `code % 7`; (4) Resolve 2-item collision with linear probing; (5) Frequency map word/event counter.
- **Levels 6–15+ (Procedural Seeded)**: Seeded key sets + table size `M` (`5..11`) guaranteed `< 75%` load factor so linear probing always terminates; deterministic hash solver verifies exact slot placement and probe count.

## 4. Feedback & Mastery
- Highlights probe sequence (`h0 -> h1 -> h2`) and contrasts total comparisons against linear search.
